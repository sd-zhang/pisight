# Delayed Audio Enable Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Remove unnecessary audio wait interrupts while preserving request ownership.
**Architecture:** Prepare requests normally; a per-endpoint hrtimer delays EPENA.
**Tech Stack:** Linux DWC2 C, Python/native-C source harness, Buildroot ARMv6.
**Spec:** ../specs/2026-09-27-audio-arm-design.md

## Global Constraints

Interval8 high-speed buffer-DMA IN only. Lead3 microframes. No changes to USB
formats, audio buffers or unrelated services. No serial, drive writes, commits
or pushes. Work in isolated source snapshots under /private/tmp/pisight-audio-arm,
then export reviewed patch to the existing nested build tree.

## Review Focus

Late timer at frame wrap must recover through NAK without stranding audio.
A dequeued never-enabled request must not wait for hardware-disable IRQs.
No callback may touch inaccessible registers after a power transition.
Giveback requeue must retain its new timer; old ownership must not leak.
Actual-arm diagnostics and size_loaded must describe the correct request.
